# Spec: Canvas editor (`@nurtuo/web`)

Status: implemented. Date: 2026-11-21.

## TLDR

A React 19 + `@xyflow/react` single-page editor for `nurtuo.flow/v1` documents: palette drag and
drop, snap to grid, marquee selection, validated connections, delete, undo/redo through the shared
CommandBus, config dialogs generated from the flow JSON Schema and live diagnostics. It loads and
saves local JSON files only; it does not talk to the control plane yet.

## Problem and goals

Integration developers want to see and edit a flow as a graph while the file format stays the
single source of truth and the canvas never produces a document the server would reject.

- Goals: every edit is a CommandBus op (same ops as MCP `apply_ops`), so undo/redo and atomicity
  are shared; connections that the validator would reject cannot be drawn; config forms follow the
  JSON Schema of each step kind; layout is view state, separate from the flow document.
- Non-goals (M1 epic 10 items not built): loading from and saving to the control plane (optimistic
  save), test mode with per-step colours, elbow edge routing, ELK auto-layout (the package
  description mentions elkjs, which is not a dependency), collaboration.

## Design (as built)

### State (`model/flowStore.ts`)

`FlowStore` wraps `CommandBus` from `@nurtuo/flow-schema`: `dispatch(ops)`, `undo()`, `redo()`,
`load(flow, positions)` (clears history), `setPositions(p)` (layout only, not in undo history).
Every change re-runs `validateFlow` from `@nurtuo/flow-validate` and publishes a `FlowState`
(`flow`, `positions`, `diagnostics`, `canUndo`, `canRedo`) to React via `useSyncExternalStore`.

### Adapter and layout (`model/flowAdapter.ts`)

`flowToGraph`/`graphToFlow` convert between the flow document and xyflow nodes/edges (edge key
`step:port`). `autoLayout` places steps by BFS depth from `start` (rows) and order within a depth
(columns); unreachable steps go one row below the deepest. `parseLoaded(text)` accepts either a flow
(`steps` + `edges`) or a layout file (`positions`), and throws otherwise. `serializeFlow` and
`serializeLayout` produce the two download files `<id>.flow.json` and `<id>.layout.json`.

### Connections (`model/connection.ts`)

`checkConnection` mirrors the validator: unknown step, port not in `portsOf(step)`, port already
connected, edge into `start`, and cycles (DFS from the target) are rejected with a reason.
`Canvas.tsx` uses it as `isValidConnection` and in `onConnect`.

### UI

- `App.tsx`: toolbar (Undo, Redo, Load JSON, Save flow, Save layout), palette from `STEP_CATALOG`
  (HTML5 drag with `DND_MIME`), canvas, side panel (selected step, diagnostics list; clicking a
  diagnostic selects its step), keyboard shortcuts Ctrl/Cmd+Z, Ctrl/Cmd+Shift+Z, Ctrl/Cmd+Y
  (ignored while typing in inputs).
- `Canvas.tsx`: custom `step` node with severity styling, `snapToGrid` with `GRID`,
  `selectionOnDrag` (marquee), `panOnDrag={[1, 2]}`, `deleteKeyCode={["Backspace", "Delete"]}`,
  drop handler that snaps and creates a step with `newStep`, `Background`, `Controls`.
- `ConfigDialog.tsx`: `role="dialog"`, fields generated by `fieldsOf(configSchemaOf(kind))`
  (`formSchema.ts`), edits applied on blur as `updateConfig` with a minimal `configPatch`, id rename
  via `renameStep` (checked against `STEP_ID_PATTERN`), label via `setLabel`.
- Text is rendered through React only; there is no `innerHTML`, `dangerouslySetInnerHTML`, `eval`
  or `new Function` in `core/web/src` (`git grep` on `main`).

## Security

- Static client-side app; it reads files the user picks and writes downloads. No network calls.
- Loaded JSON is parsed with `JSON.parse` and type-checked shallowly; rendering goes through React,
  so step labels or diagnostics cannot inject markup.
- When the canvas starts talking to the control plane it will need CSRF/CORS and token handling;
  none exists yet.

## Gaps and risks

| # | Scenario (concrete) | Severity | Area | Mitigation / follow-up |
|---|---|---|---|---|
| 1 | The Playwright suite is not in any CI job (`ts` runs `turbo run test`, which is Vitest only). A change that breaks drag and drop or the config dialog ships green; the 10 e2e tests are only run by hand. | high | testing | Add a `web-e2e` job: `pnpm exec playwright install --with-deps chromium` and `pnpm --filter @nurtuo/web test:e2e`, upload traces on failure ([quality-gates](../2026-11-22-quality-gates.md)). |
| 2 | The canvas cannot open or save a flow in the control plane; `@nurtuo/client` is a declared dependency but is not imported. Users edit files and push them with `nurtuoctl`. Epic 10 "optimistic save" and "test mode" are not met. | high | scope | Track in [m1-acceptance-review](../2026-11-22-m1-acceptance-review.md); a follow-up spec for control plane integration (revision conflicts, auth). |
| 3 | Keyboard and screen-reader users cannot build a flow: palette items are `draggable` `div`s with no keyboard alternative, diagnostics are `li` elements with `onClick` only, the config dialog has no focus management or Escape handling. | medium | accessibility | WCAG 2.2 AA pass: "add step" buttons, focusable diagnostics, focus trap and Escape in the dialog, `aria-live` diagnostics count; axe check in Playwright. |
| 4 | Config fields apply on blur. Typing into a field and clicking "Save flow" directly may download the document before the blur's `updateConfig` lands, losing the last edit (no e2e test covers it). | medium | data loss | Apply on change with debounce or flush pending fields before save; add an e2e case. |
| 5 | `parseLoaded` checks only that `steps` and `edges` exist. A file with a step missing `id` or with a non-string `kind` reaches `CommandBus` and xyflow and can throw during render, leaving a blank canvas instead of the error message. | medium | robustness | Validate with the flow JSON Schema before `store.load`; React error boundary around the canvas. |
| 6 | `autoLayout` is O(steps × edges) per BFS step and runs on every `load`; ARCHITECTURE.md §9 targets 250 steps at 60 fps, which is not measured. | low | performance | Index edges by source; add a 250-step Playwright performance check. |
| 7 | The layout file format is undocumented and not versioned; a later format change silently ignores old layout files. | low | contract | Add `schema: nurtuo.layout/v1` and document it. |
