# Flow format and validation rules (flow.v1)

Source of truth: `sdk/ts/flow-schema/schema/flow.v1.schema.json` (JSON Schema 2020-12).
Representations kept consistent with it:

| What | Where | How it is kept consistent |
|---|---|---|
| TS module of the schema | `sdk/ts/flow-schema/src/schema.generated.ts` | generated by `pnpm --filter @nurtuo/flow-schema run sync` (also part of `build`), checked by `schema.test.ts` |
| Go copy (embedded) | `sdk/go/flow/flow.v1.schema.json` | same script; checked by `TestSchemaCopyInSync` and `schema.test.ts` |
| TS types / Go structs | `flow-schema/src/types.ts`, `sdk/go/flow/flow.go` | hand-written, not generated; checked by the kind list test and by the conformance corpus |

Both validators run the shared corpus in `sdk/ts/flow-schema/testdata/conformance/{valid,invalid}`.
Each file is `{description, flow, expect:[{severity, code, path, stepId?}]}`; messages are not
compared. Diagnostics are de-duplicated and sorted by (path, code, stepId).

## Assumption

`docs/ARCHITECTURE.md` refers to "validator rules from reference Part III section 5", but the
reference document (`boomi-architecture-reference.md`) is not in this repository. The rules below
are derived from the architecture document (one start, DAG engine, set-at-a-time Branch, per-port
edges, "canvas and AI agent validate identically") and standard flow-validity needs. When the
reference is available, reconcile this list with it; the corpus is the place to change.

## Ports

| Kind | Ports | Notes |
|---|---|---|
| start | `default` | no incoming edges allowed |
| connector, queue, map, script, message, setProperties, processCall, notify | `default` | |
| decision | `true`, `false` | |
| branch | `1`..`paths` | `paths` 2..25 |
| route | each route id, then `default` | `default` is reserved as a route id |
| tryCatch | `try`, `catch` | |
| stop, returnDocuments | none | terminal |

Every port must have an outgoing edge, so every path ends in a terminal step.

## Rules

Stage 1, `schema.*` (type, const, enum, pattern, minLength, minimum, maximum, minItems, required,
additionalProperties): the document must match the JSON Schema, including the per-kind `config`
shape. If stage 1 reports errors, stage 2 does not run.

Stage 2 (errors unless noted):

| Code | Meaning |
|---|---|
| `step.duplicate_id` | step id used twice (reported on the later step) |
| `flow.start_count` | not exactly one `start` step (`/steps` if none, each extra start otherwise) |
| `edge.source_unknown` | edge key names a step that does not exist |
| `edge.target_unknown` | edge target step does not exist |
| `edge.port_invalid` | source step has no such port (includes any edge out of a terminal step) |
| `start.has_incoming` | an edge targets a start step |
| `step.port_unconnected` | a port of the step has no edge (path points at the missing edge) |
| `flow.cycle` | step can reach itself (the M1 engine interprets a DAG) |
| `route.duplicate_id`, `route.reserved_id` | route ids must be unique and not `default` |
| `setProperties.duplicate_name` | same name set twice in the same scope in one step |
| `processCall.self_reference` | `config.flow` equals the flow's own id |
| `step.unreachable` (warning) | not reachable from a start step; skipped when there is no start |

Not checked (needs context outside one flow): existence of called flows, connectors, queues and
connections; CEL/JSONata syntax. Those belong to deploy-time validation.

## CommandBus

`@nurtuo/flow-schema` exports `applyOps(flow, ops)` (pure, atomic, never mutates its input) and a
`CommandBus` with undo/redo. Ops: `addStep`, `removeStep`, `updateConfig` (RFC 7386 merge patch),
`connect`, `disconnect`, `setLabel`, `renameStep`. Ops check referential integrity only; validity
is the validator's job.

## Script step

`script` runs a sandboxed WASM module over each document (see `docs/scripts.md`). Config:
`script` (required, name of a registered script module), `timeoutMs` (1..600000), `memoryMiB`
(1..4096) and `capabilities` (unique, each `clock` or `random`). Whether the named module exists is
deploy-time validation, like connectors.
